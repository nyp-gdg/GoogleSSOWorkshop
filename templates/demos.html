Act 1

Fundamental Authentication Concepts

Test and inspect how different authentication mechanisms transport credentials across HTTP requests.

HTTP Header

1. Basic Auth

Sends credentials in Authorization: Basic base64(user:pass) on every request.

GET /demo/basic-auth Default test credentials: sofia : secret
Stateful Cookie

2. Stateful Session Auth

Logs in via POST. The server generates an opaque Session ID, stores { session_id: user } in an in-memory table, and sets a demo_session_id cookie.
Notice: If the server reboots or restarts, the in-memory session table is wiped clean and the cookie can no longer be verified!

POST /demo/session-login & GET /demo/session-profile
Stateless Token

3. Stateless Bearer Auth

Step 1: Exchange user credentials for a signed JSON Web Token (JWT).
Step 2: Send token in Authorization: Bearer <token> to verify claims statelessly without DB lookup.

POST /demo/bearer-token (Issue Token) & GET /demo/bearer-auth (Verify Token)

Summary

Auth Architecture Comparison

Mechanism Credential Transport State Storage Revocation Use Case
Basic Auth Authorization: Basic base64 Stateless (sent every request) Difficult (browser cache) Legacy internal tooling / scripting
Stateful Session Auth Opaque Cookie (demo_session_id) Server Memory Table (DEMO_SESSIONS) Instant (cleared on server / logout) Traditional multi-page web applications
Stateless Bearer Auth Authorization: Bearer <token> Stateless (Self-contained JWT) Short expiry + refresh tokens REST/GraphQL APIs, Mobile apps, SPAs
Google SSO (OIDC) Authorization Code → ID Token Decoded claims in app session Google IdP session User identity & frictionless authentication
OAuth 2.0 Delegation Access & Refresh Tokens Secure server-side token store User Revocation (Google Account) Third-party resource access (e.g. Tasks API)
